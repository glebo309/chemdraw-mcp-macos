# Compatibility and limits

Updated 2026-09-15. Source inspection and application discovery are not native compatibility tests.

| Component | Current evidence |
|---|---|
| Desktop application | ChemDraw 23.0.1 on the development Mac is the only locally live-tested version |
| macOS/processor combinations | No cross-version or cross-architecture certification matrix yet |
| Python | Package requires 3.11 or newer; use the locked environment |
| MCP SDK | Dependency constrained to `>=1.27.1,<2`; no SDK v2 claim |
| Interface | AppleScript/AppleEvents through the installed application; no simulated clicks |
| Windows/Linux | No native backend here; portable tests do not establish native application support |
| RDKit | Optional for basic bridge; required for offline identifiers/proposals, draw coordinate seeds and high-level graph validation; installed version follows the selected environment |

Opt-in native tests exercise the stdio MCP bridge, bounded native polish, analogue edits for oxygen-to-sulfur, oxygen-to-nitrogen, carbonyl formation and a remote halogen change retaining tetrahedral stereo, plus scope grids and a disconnected sodium/chloride compound. These tests check preservation of pre-existing document state. See [project progress](../PROJECT_PROGRESS.md) for current run results. Rerun tests when modifying native behavior or upgrading ChemDraw; future compatibility claims need exact environment records and reproducible tests.

## Supported operations

Optional scope decorations form a separate supported finishing pass: native rounded shadow frames, actual dotted separators and explicit headings for existing nonoverlapping bands. Molecules and captions stay fixed. The fourteen-candidate example was visually checked in native SVG and corrected transparent PNG. General graphics, automatic category inference and reordered groups are not implied. See [scope decoration](SCOPE_DECORATION.md).

- Native list/inspect, current document IDs, document settings and 1-based molecule indices.
- Native CDXML creation/import/export and CDX/SVG/PDF export. PNG rasterizes unchanged native SVG offline with pinned resvg-py 0.5.0. External SVG resources are rejected; no rasterizer fallback. System fonts are used and still require visual review.
- Low-level MOL/SDF import routes exist. The `draw` workflow uses private MOL seeds; exact native fixture evidence belongs in the progress log, not a general import-format certification claim.
- Explicit native cleanup with recovery snapshots; never automatic inside polish.
- Style copies and conservative flat, single-page polish with optional explicitly owned row layout.
- Native post-export chemical-preservation checks for the supported subset.
- Single-molecule analogue copies through CLI and MCP, using explicit neutral atom/H and plain bond-order edits on copied CDXML, followed by native ChemDraw save/render and mapped verification.
- Scope-grid copies through CLI and MCP, with explicit compound/fragment/caption ownership, caller-supplied IDs and optional yields, uniform native-measured cells and saved-page fit verification.
- Batch export through CLI and MCP of explicit supported CDXML files, with stable figure keys, default CDXML/SVG/PNG plus requested PDF/CDX, per-item audits, source snapshots and a contact sheet. No style or layout transformations run.
- Electron-flow annotation copies through CLI and MCP, with explicit atom/bond or source-symbol references and cubic controls. Full two-electron heads and both one-electron fishhook sides are supported. Annotation retains existing supported symbols; new symbols use the separate copy workflow.
- Offline strict SMILES/canonical Standard InChI inspection, with explicit H/isotope/stereo/component summaries and separate InChI normalization reporting. No native application or external naming service is called.
- Offline standard aromatic scope proposals from an explicit mapped parent, with fourteen deduplicated reference/electronic/halogen/positional/steric candidates, relative labels and null yields. These are proposals, not chemical-compatibility or reaction predictions.
- Native new-structure drawings from explicit SMILES/label records. RDKit supplies validated MOL coordinate seeds; ChemDraw imports, runs native cleanup and renders. The native-measured grid workflow supplies final scale, labels and page-fit checks.
- Explicit one-step reaction composition from one through three reactants/products per side, caller-supplied conditions, native arrow/plus signs and measured role/caption/spacing/page checks. [Reaction boundaries](REACTION_BUILDER.md)
- Read-only local `.cds`/`.cdx`/`.cdxml` style extraction and validated custom presets. The rendering Mac checks actual label/caption font families before native production. No template artwork, page geometry, palette or font files are imported. [Style boundaries](STYLE_IMPORT.md)
- PubChem name/CAS candidate resolution only with explicit per-call network opt-in. Provider associations, ambiguity, truncation and strict graph validation remain distinct; no candidate is automatically selected. [Resolver boundaries](RESOLVER.md)
- Explicit mapped H-carbon scans on isolated neutral five/six-membered aromatic C/N/O/S rings, including existing substituents; ten curated groups and at most 100 requested candidates before deduplication. [Expanded scope boundaries](SCOPE_EXPANDED.md)
- A separate symbol-copy workflow adds native lone-pair/circled-charge symbols or graphical electron dots, with explicit atom requests and bounded placement. Circled charges require an existing formal +1/-1. Electron dots use native filled-circle graphics because nearby native Electron Symbols would change Radical state. Four native MCP cases passed on this Mac: negative-charge creation, lone-pair creation plus a source arrow, graphical-electron creation plus a fishhook, and an existing negative-charge source arrow. No chemical charge or radical-state edits are authorized. Consult [symbol boundaries](SYMBOLS.md) for tested scope and calibration.

Polish rejects grouped drawings, nested abbreviations, polymers, atom/bond queries, enhanced stereo and unsupported graphical objects. Native arrow fallback graphics marked as superseded are handled specifically; arbitrary decorative page graphics are not a supported layout surface.

The v0.9 additions provide complete explicitly approved scope jobs, up to three explicit reaction rows on one page, ownership-sidecar movement, bounded route proposals and portable numerical lab styles. See [scope jobs](SCOPE_JOB.md), [expanded reactions](REACTION_EXPANDED.md), [ownership/routes](OWNERSHIP.md) and [lab styles](LAB_STYLE.md). These are independently bounded workflows, not blanket support for all ChemDraw objects.

Not implemented: native Name-to-Structure, additional name providers, unrestricted atom editing or insertion/deletion in existing ChemDraw documents, arbitrary substituent attachment, automatic common-core inference, automatic sugar reorientation, general collision-free charge placement, chemical radical-state editing, native manual-drag arrow attachment, multipage layout or inferred reaction sequences. Route suggestions require explicit anchors and selection; they do not infer mechanisms or certify native arrowhead ink. The scope proposers attach only curated groups to supported parents; symbol placement uses bounded conservative checks rather than a general collision solver. ChemDraw being able to display an object does not mean a workflow can safely transform it.

Analogue editing is narrower than polish: one molecular fragment plus optional captions, no reaction, multiple fragments or molecular graphics. Atom edits support neutral C/N/O/F/P/S/Cl/Br/I targets with explicit hydrogen counts; isotope-labelled or charged target atoms are rejected. Bond-order edits require plain nonaromatic, nonstereo bonds. Existing stereocentres cannot be edited, and changes that create/remove potential tetrahedral or alkene stereo fail closed. Every caption requires an explicit replacement, retention or removal. Live-document recipes require the source token returned by current analysis. This is copied-CDXML editing, not a native atom-setter API.

Scope grids accept one flat, single physical page of supported fragments and owned captions, with 1 through 100 explicit compounds. Every fragment and every page-text object must have one owner. Multiple fragments can belong to one compound and translate together after per-fragment normalization. Reactions, unowned text, nested groups, page graphics and native symbol graphics inside molecules are unsupported. Plain formal-charge atom attributes are supported; native circled-charge symbols are not the same object type. The sodium/chloride native fixture establishes one disconnected-ion case, not arbitrary salt or organometallic support. A live grid requires the top-level `source_token` returned by current analysis, not a single-molecule editing report.

Batch export accepts 1 through 100 explicit UTF-8 CDXML files, each at most 10 MB, with case-insensitively unique safe figure keys. It supports flat fragments, page text, arrows, native superseded arrow-fallback graphics and reaction-scheme metadata, plus the restricted annotation subset described below. Supported full/half-headed cubic curves and existing circled-charge associations/geometry/styling are verified by the annotation verifier; unknown curve/symbol shapes or properties and other molecular/atom graphics remain rejected. CDX/MOL/SDF are not batch inputs even though some low-level import routes exist. Per-item frozen-source and post-export CDXML snapshots live below `snapshots/`, separate from named exports. Source graphs/positions and explicit reaction roles are checked after native import; any reaction scheme inferred by ChemDraw is not chemically certified.

Batch input failures are reported individually and valid items may still export. Any native-operation exception stops further items without retries or automatic closure of an uncertain working document. Successful copies are closed; pre-existing document IDs, metadata and exported unsaved content are checked, with those document recovery snapshots kept in workspace backups rather than the contact sheet. Source-file hashes and native working content are also checked. A mixed-failure batch exits nonzero. Status and artifact availability must be read together: an existing image from a failed or uncertain item is not an approved figure. See [batch usage](USAGE.md#batch-export) and [project progress](../PROJECT_PROGRESS.md) for the current evidence and run results.

Annotations accept a flat, single-CDXML-page subset with supported molecular fragments, page text, reaction arrows/schemes and native arrow fallback graphics. Molecular graphics accept `CirclePlus`/`CircleMinus` with matching formal-charge references, native lone pairs, and the strict graphical electron subset. A LonePair native `represent attribute="Radical"` association must refer to a nonradical atom in its own fragment and preserve chemistry. New electron dots are native black `Oval` / `Circle Filled` graphics with verified circular geometry and no chemical association; they are not Electron radical-state symbols. Existing unassociated Electron Symbols are accepted only without chemistry changes. Unknown graphic properties, unsupported associations and Radical state changes fail closed. Existing curves must be one cubic segment with a supported full/half head; unsupported shapes, styles and nonfinite/nonpositive dimensions are rejected. Batch reuses this verifier; the new symbol/source-arrow native cases do not imply that every graphical mixture has been batch-tested. Grids, `draw` and polish do not accept these annotation graphics.

Explicit symbol-source arrows support negative-charge/lone-pair full arrows and electron-dot fishhooks. Positive-charge sources, symbol targets and source-symbol offsets are rejected. The departure tangent selects a visible-edge point using ChemDraw 23.0.1 SVG calibration; a lone pair starts from an actual dot, not the space between dots. Native charge/lone-pair/graphical-electron source-arrow cases passed on the development Mac. This does not certify every full curve path, chemical intent or another ChemDraw version. Consult [symbols](SYMBOLS.md) and [mechanism conventions](MECHANISM_CONVENTIONS.md).

The annotation recipe supplies 1 through 50 curves. Atom/bond endpoints use an existing atom position or bond midpoint plus a finite `[dx, dy]` offset, with each coordinate bounded by 36 pt. A source-only symbol endpoint instead uses its explicit symbol ID without an offset. Two control offsets, each coordinate bounded by 200 pt, are relative to the start and end. New line width is 0.2 through 3 pt. A live document requires a current annotation source token; file input requires native-measured bounds for labelled atoms used as endpoints. Native curves remain editable, but atom/bond ownership is recorded in the recipe rather than asserted as ChemDraw moving attachment. No molecular or radical-state edits are performed.

File-input grids freeze source bytes before native creation and retain them as `source-input.cdxml`, with original path, SHA-256 hash and preservation result in the audit. Detected source mutation/disappearance fails production. Uncertain native outcomes are not retried or followed by automatic source closure; uncertainty during the final source-close operation also changes the audit status to `uncertain`. This does not prevent concurrent external changes to files or documents.

Offline identifier inspection is broader than native drawing: disconnected components and some radical/elemental graphs can be described without being supported by `draw`. SMILES retain explicit H and supported isotope/tetrahedral/E/Z stereo; queries, dummy atoms, atom maps, trailing names/CX data, discarded stereo and exotic bonds/stereo are rejected. InChI input is canonical Standard InChI only with exact regeneration. Standard InChI output may normalize the graph, so availability, warnings and roundtrip equivalence are separate fields. See [identifier semantics](IDENTIFIERS.md).

The standard scope profile requires a connected parent of at most 200 atoms with an explicit unique map on the carbon attaching the reaction handle to an isolated monosubstituted benzene ring. Its five other sites carry H. The separate custom scan accepts explicit mapped H-bearing carbon sites on pre-substituted or heteroaromatic isolated five/six-membered rings. Selected rings remain neutral and non-isotopic; fused rings are rejected. Both profiles restrict parent atoms to C/N/O/F/P/S/Cl/Br/I and reject explicit H nodes, radicals, queries, unassigned potential stereo and non-tetrahedral/directional stereo. Existing supported graph/stereo is checked. Atom-map ownership is never inferred. Relative labels are not systematic names, IDs are graph-derived rather than registry IDs, and compatibility/availability is not predicted. Review and selection precede drawing.

Style extraction accepts only its documented numerical/font subset; duplicate font tables/IDs, unresolved font references and malformed binary data fail closed. The documented 28-byte CDX header and specifically observed local 22-byte native layout are both supported. Import reports expose defaults and unapplied root/document properties, not a complete template-content audit. Source bytes are reread and compared; extracted custom settings are recorded in drawing requests. Native visual checks remain distinct from font-family availability and successful parsing.

The original connected reaction path reuses the 2 through 150-atom nonradical drawing subset and optionally aligns an explicit scaffold matching all participants. The expanded path accepts supported water, hydroxide, halide and alkali-ion participants plus bounded charge-balanced disconnected salts and explicit positive coefficients. It retains native page settings, rejects overflow and never invents coefficients, products, yields or conditions. Expanded reaction/scaffold alignment is explicitly unsupported. Up to three explicit rows may share one editable page; no intermediate links or products are inferred. New symbol requests are separate from reaction construction. Symbol placement uses measured labels, calibrated visible glyph circles and a search bounded at 36 pt; collision checks cover bond centre-lines with configured stroke allowance, not all rendered bond ink, wedges or double-bond outlines. Curve-control bounds alone do not establish full-path clearance; the separate route planner uses its documented conservative chord model. These calibration rules are tested on ChemDraw 23.0.1 only. Ordinary grids and draw do not automatically gain support for annotation graphics.

Native `draw` accepts 1 through 24 records, each exactly `compound_id`, `label` and `smiles`. Each molecule is connected, nonradical and 2 through 150 atoms, using H/B/C/N/O/F/Si/P/S/Cl/Br/I. Labels are caller-supplied and unverified as names. Plain formal-charge atoms must survive the native parser/preservation checks; disconnected salts, reaction objects and native circled-charge graphics are outside this creation path. The composition retains the first native import's page settings. Positive scale normalization and conservative native-molecule/estimated-label bounds determine nonoverlapping uniform staging cells before import, followed by native-measured grid-fit verification. A CDXML bounding box alone does not establish a custom physical page size. Preset, columns, PNG size and optional explicit `scaffold_smiles` are configurable; yields and page resizing are not. See [draw usage](USAGE.md#draw-native-structures-from-smiles) and the progress log for actual native run evidence.

Optional draw alignment requires a connected nonradical explicit SMILES scaffold of 3 through 150 heavy atoms, without explicit H nodes. Every input must contain a compatible match before any native call. After preset normalization, native coordinates align to the first structure by proper rotation and translation only, with no reflection or alignment scaling. Noncollinear scaffold geometry and a fit RMSD of at most 0.25 pt are required. Symmetric matches use deterministic index/rotation tie-breaking, not inferred correspondence beyond the supplied core; excessive matches fail. Native saving must remeasure rotated labels before final grid-fit checks. This is not automatic scaffold discovery, intramolecular collision certification or prescribed sugar orientation. On the development Mac, two live draw/MCP tests passed, and the fourteen-candidate aligned CLI example passed native checks and visual inspection. Its largest normalized scaffold-fit RMSD was 0.0026354 pt. These fixtures do not establish compatibility with other ChemDraw versions.

There is no server image-recognition endpoint. A connected image-capable client can transcribe a hand sketch to an explicit graph, but ambiguous atoms/bonds/stereo require resolution and the graph-to-image correspondence is not validated by identifier parsing. No additional image model/provider is part of this package.

## Geometry and chemistry

Normalization positively scales entire molecular fragments and preserves orientation. Equal median bond length is not equal molecular width and does not repair an internally distorted structure. The annotation workflow verifies explicit existing charge-symbol association; general charge collision resolution is not implemented.

`draw` differs from polishing existing drawings: it first generates new MOL coordinates and runs native cleanup on its own imported copies. Existing seed orientations are therefore not promised. Identity is checked after MOL writing, native import, cleanup and composition, then the grid stage retains the resulting native orientations. Atom-label and measured-bounds checks do not certify all final glyphs or intramolecular collisions. Pre-existing document inventory/metadata and exported contents are checked; native uncertainty stops without retries or automatic closure of the uncertain copy.

Row layout requires explicit caption/condition maps and rightward horizontal arrows. `width` constrains main row objects and gaps, not every caption or the printed page. Source chemical correctness is outside the preservation check.

Scope-grid fit is different: native molecular and caption ink bounds determine common cell dimensions, and all final object ink must fit within the saved-page region and margins. Compounds retain recipe order and orientation; name/metadata baselines align within each row. Explicit or automatically chosen columns never reduce molecule scale to avoid overflow. Long captions can therefore cause a rejected grid. Verification includes native visible caption centring within 0.75 pt, ownership, compound/yield text bindings, mapped chemistry and inter-object overlaps. It does not detect every intramolecular collision, optimize common-scaffold alignment, validate supplied yields, resize the page or certify printed output.

The validator retains explicit H and rejects partial atom/fragment parsing. It must evaluate depicted supported stereo instead of blindly trusting stale cached assignments; native stereo/cache and bond-ordering handling are implementation-sensitive and covered by regression fixtures. Unsupported chemistry is an error, not a successful preservation result.

Analogue verification compares the requested graph and mapped stereo to native saved CDXML, checks each atom's preserved coordinates, and separately compares chemical label tokens and caption text. `native_labels_verified` means CDXML content was checked, not that SVG/PNG glyphs passed visual validation. The edit path has no general collision detector or automatic charge/label positioning. An incorrectly ordered input atom label was found through visual inspection and corrected using a native export probe; see [known issues](KNOWN_ISSUES.md). This is not evidence of a general native SVG bug. Visual review remains mandatory.

Annotation verification checks mapped source chemistry and atom coordinates, supported symbol counts, associations, geometry and styling, and curve counts, heads, controls and styling after native saving. For atom endpoints, clearance checks only the referenced atom's measured label box expanded by 1 pt, or a 1 pt distance from an unlabelled atom. Explicit symbol sources instead use the calibrated glyph-edge rule described above. Neither endpoint rule checks the entire curve, arrowhead, unrelated glyphs, other curves, page fit or chemical plausibility. Source document content/metadata and available file hashes are checked; file input also retains and rechecks its byte hash. Visual review remains required. Native-operation errors stop without retry or automatic closure of the uncertain copy.

## Native findings

- Document IDs work and can be negative. The declared native molecule ID getter fails in the tested application; use refreshed 1-based indices for low-level molecule operations.
- ChemDraw may renumber CDXML objects on import. Recipes are matched by chemistry/text and geometry, with ambiguous matches rejected. Native rounding tolerance is currently 0.03 pt.
- Native settings use twentieths of a point. A requested 1.58 pt line may be reported as 32/20 pt.
- Setting `BondLength` does not rescale existing coordinates. Native cleanup is not a reliable substitute for explicit scale normalization.
- The native SVG format name is `Scalable Vector Graphics (SVG)`.
- With Foundation loaded, AppleScript file coercions must occur outside the application's `tell` scope to avoid observed path errors.
- An import can briefly exist before document identification catches up. The bridge uses bounded read-only discovery to identify its opened copy rather than repeating the open write.
- Source-preservation checks include document state, available on-disk hashes and exported unsaved content, ignoring export/window metadata. They do not prevent an external editor from changing the document concurrently.

## Diagnostic boundary

`doctor` checks discovery/version metadata and optionally lists documents. It reports RDKit and rasterizer availability but does not execute chemistry validation or an image export. `doctor --no-connect` leaves native connection untested.

Licensing, Automation permission, modal dialogs and competing clients can still interrupt native operations. Timeouts are not blindly retried. The tool does not activate licenses, change permissions, dismiss arbitrary dialogs or expose a network control endpoint.

Offline identifier conversion remains provider-free. The separate [PubChem resolver](RESOLVER.md) sends only its explicitly supplied query after per-call opt-in, returns at most 20 candidate records and never automatically selects a match. CAS checksum validation is not Registry certification. Redirects, retries and provider fallback are disabled. See its contract for response limits, ambiguity and timeout behavior. Additional providers and native naming commands remain unimplemented.
